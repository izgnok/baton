# Claude Rooms 설계

- 작성일: 2026-11-26
- 레포: `izgnok/claude-rooms` (로컬 `~/claude-rooms`, 이 문서는 `docs/`)
- 상태: 설계 검토 대기

## 1. 목적

서로 다른 Claude 계정을 쓰는 사람들이 각자 자기 컴퓨터에서, **같은 채팅방의 같은 Claude 대화**를 보며 함께 작업한다.
Claude 실행 사용량은 메시지를 보낸 사람의 계정에서 나간다. 메모리와 결과물(md, HTML)은 방 안에서 공유한다.

### 성공 기준
- 맥 두 대, 계정 두 개로 같은 방에 들어가 같은 대화 내역을 실시간으로 본다.
- A 가 `@claude` 로 시킨 다음 B 가 `@claude` 로 이어 시키면, Claude 가 A 때의 대화를 기억한 채로 B 계정으로 답한다.
- 방 메모리와 결과물이 두 맥에 똑같이 보인다.

| 37 | (2026-11-27) 방 컨텍스트 크기 표시: 서버가 방 대화 원본의 마지막 Claude 답 사용량(input + cache 만들기·읽기 + output)과 모델을 계산해 방 상태(`context: {tokens, model}`)에 넣고, 대화 원본을 쓸 때마다 방 멤버 모두에게 다시 보낸다(압축 뒤 아직 답이 없으면 null). 같은 대화를 이어 쓰므로 방마다 하나, 누가 어느 맥에서 봐도 같은 값 — 세션을 정말 같이 쓰는지 보는 표시이기도 하다. 맥 앱 방 머리줄에 "컨텍스트 14% · 14.5만/100만"과 막대(80% 이상 경고색). 컨텍스트 창은 지금 고를 수 있는 모델 모두 100만 토큰 |

## 3. 범위 밖

- Claude 계정으로 이 앱에 로그인하는 것. Anthropic 정책상 제3자 앱이 claude.ai 로그인을 제공하는 것은 금지다([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance.md))

## 4. 전체 구조

```
              ┌──────────── 서버 (맥1, Node) ────────────┐
              │ 회원 · 방 · 메시지 · 실시간 중계 (웹소켓)  │
              │ 방별 Claude 대기열과 실행 잠금            │
              │ 대화 원본(jsonl) · 공유 파일 보관          │
              │ 저장: SQLite + 파일                      │
              └──────▲───────────────────────▲──────────┘
                     │                       │
     ┌───────────────┴──────┐   ┌────────────┴─────────┐
     │ 앱 (맥1, A 계정)      │   │ 앱 (맥2, B 계정)      │
     │ 화면 + 실행기         │   │ 화면 + 실행기         │
     │ 실행기 → claude CLI   │   │ 실행기 → claude CLI   │
     └──────────────────────┘   └──────────────────────┘
```

구성은 세 부분이다. 서로 아래 인터페이스로만 대화한다.

| 부분 | 하는 일 | 의존 |
|---|---|---|
| 서버 | 회원, 방, 메시지, 대기열, 대화 원본, 공유 파일 | Node 24, `ws`, `node:sqlite` |
| 앱 화면 | 로그인, 방 목록, 채팅, 레포·공유 파일·멤버 패널, 승인 창 | Electron 렌더러 |
| 앱 실행기 | 실행 전 점검, 대화 원본·공유 파일 내려받기, `claude` 실행, 결과 올리기 | Electron 메인 프로세스, `claude` CLI, `git` |

## 5. 서버

### 5.1 데이터

SQLite 테이블:

| 테이블 | 컬럼 |
|---|---|
| `users` | id, email, password_hash, name, created_at |
| `sessions` | token, user_id, created_at |
| `rooms` | id, name, invite_code, owner_id, claude_session_id(처음엔 null), transcript_version, created_at |
| `room_members` | room_id, user_id, joined_at |
| `room_repos` | id, room_id, name, remote_url, branch |
| `messages` | id, room_id, user_id, kind, body, status, created_at |

- `messages.kind`: `chat`(사람끼리) · `claude_request`(`@claude` 요청) · `claude_event`(Claude 스트리밍 결과 조각) · `system`(입장, 퇴장, 오류)
- `messages.status`(`claude_request` 만): `queued` → `running` → `done` / `failed` / `held`
- 파일 저장: `data/rooms/<방id>/transcript.jsonl`(대화 원본), `data/rooms/<방id>/shared/...`(공유 파일)
- 비밀번호는 `node:crypto` scrypt 로 해시한다.

### 5.2 방 규칙
- 방장 = 만든 사람. 레포 관리와 방 삭제는 방장만 한다.
- (제안) 방장이 나가면 가장 먼저 들어온 멤버가 방장이 된다. 마지막 사람이 나가면 방은 남겨 둔다.

### 5.3 대기열
- 방마다 `claude_request` 를 들어온 순서대로 하나씩 처리한다.
- 맨 앞 요청 차례가 되면 서버가 **보낸 사람의 앱**에 실행을 맡긴다.
- 실행 중인 앱은 10초마다 신호를 보낸다. (제안) 30초 동안 신호가 없으면 그 요청을 `failed`(중단됨)로 바꾸고 다음으로 넘어간다.
- (제안) 차례가 왔는데 보낸 사람 앱이 오프라인이면 그 요청은 `held`(보류)로 두고 다음으로 넘어간다. 보낸 사람이 다시 접속하면 [다시 보내기]로 대기열 끝에 넣는다.

### 5.4 대화 원본 버전
- 서버가 `transcript_version` 을 들고 있다. 앱은 실행 시작 때 받은 버전을 기억했다가, 끝나고 올릴 때 같이 보낸다.
- 버전이 다르면 서버가 거부한다. 대기열이 한 번에 하나씩만 돌리므로 정상 흐름에서는 생기지 않고, 잠금이 시간 초과로 풀린 뒤 늦게 도착한 결과를 막는 용도다.

## 6. 앱 실행기: `@claude` 한 번 처리

1. **실행 전 점검**: 방 레포마다
   - 로컬 폴더가 있는지, `git remote get-url origin` 이 방 레포 주소와 같은지 → 다르면 **막음**
   - 현재 브랜치가 방 지정 브랜치인지 → 다르면 **막음**
   - 커밋 안 된 변경, 원격보다 뒤처짐 → **경고만** 보여 주고 진행
2. **내려받기**: 서버에서 대화 원본과 공유 파일 중 바뀐 것만 받는다.
   - 대화 원본은 이 맥의 Claude 가 찾는 위치에 쓴다: `~/.claude/projects/<인코딩된 방 폴더>/<claude_session_id>.jsonl`
3. **프롬프트 만들기**: 직전 Claude 실행 이후의 `chat` 메시지를 앞에 붙인다.
   ```
   [방 대화]
   A: 이 API 응답 구조 어때?
   B: 페이징은 빼도 될 듯

   [요청 - A]
   페이징 빼고 구현해줘
   ```
4. **실행**: 작업 폴더는 `~/.claude-rooms/<방>/`(안에 `shared/`)로 한다.
   ```
   claude -p "<프롬프트>" \
     --resume <claude_session_id>            # 방의 첫 요청이면 생략
     --output-format stream-json --verbose \
     --add-dir <레포 로컬 경로 …> \
     --append-system-prompt "<방 메모리 목차>" \
     --mcp-config <앱의 승인용 MCP 설정> \
     --permission-prompt-tool mcp__rooms__approve
   ```
   - 첫 요청이면 스트림의 시작 이벤트에서 세션 ID 를 받아 서버에 등록한다.
   - 스트림 이벤트는 받는 대로 서버로 보내고, 서버가 방 전체에 뿌린다.
5. **권한 질문**: Claude 가 `mcp__rooms__approve` 를 부르면 앱의 작은 MCP 서버가 받아 **보낸 사람 화면에만** 승인 창을 띄운다. 방 사람들에게는 "A 승인 대기 중"이 보인다. 각자 `~/.claude/settings.json` 에 허용해 둔 명령은 묻지 않는다.
6. **올리기**: 끝나면 바뀐 대화 원본과 `shared/` 에서 바뀐 파일을 올리고 요청을 `done` 으로 바꾼다.

### 6.1 레포 연결과 방 전용 작업 폴더 (2026-11-26 변경)
- 원본 레포 경로는 맥마다 다르므로 앱 로컬 설정(`~/.claude-rooms/config.json`)에 둔다. 없으면 [clone] — 기본 위치 `~/.claude-rooms/repos/<레포 이름>`.
- 방 전용 작업 폴더: `~/.claude-rooms/<방>/repos/<레포id>-<이름>`. 원본 레포에서 `git worktree add --detach` 로 만든다. **항상 detached HEAD** 로 두어, 원본 폴더가 같은 브랜치를 쓰고 있어도 충돌하지 않는다.
- 실행 전: `fetch origin <방 브랜치>` → 원격에 없으면 막음(`BRANCH_NOT_ON_REMOTE`). 작업 폴더를 `rebase --autostash origin/<방 브랜치>` 로 맞춘다(방 브랜치가 바뀌었으면 그 브랜치로). 충돌이면 rebase 를 되돌리고 막음(`SYNC_CONFLICT`).
- 실행 뒤: 레포마다 작업 폴더의 변경(파일 목록, diff 앞부분, push 안 한 커밋 수)을 채팅에 한 덩어리로 보여 준다. 커밋·push 는 결정 5·16·17·18 대로 Claude 가 사람 지시를 받아 한다.
- 레포 삭제·방 나가기: 작업 폴더에 커밋 안 됐거나 push 안 된 변경이 없으면 `git worktree remove`, 있으면 남겨 두고 알린다.
- [레포] 탭: 원본 폴더, 방 작업 폴더(+[폴더 열기]), 상태, 보호 브랜치 안내.

### 6.2 공유 파일과 메모리
```
~/.claude-rooms/<방>/shared/
  memory/     방 메모리 (목차: memory/INDEX.md)
  outputs/    md 결과물, HTML 아티팩트
```
- 방 메모리 목차는 매 실행 때 `--append-system-prompt` 로 붙인다. Claude 는 새로 안 사실을 `shared/memory/` 에 적는다.
- 각자의 `~/.claude` 규칙·스킬·개인 메모리는 공유하지 않는다. 그래서 보낸 사람에 따라 Claude 동작이 조금 다를 수 있다. 방 전체에 같게 적용할 규칙은 방 메모리에 적는다.
- HTML 아티팩트는 `shared/outputs/*.html` 파일이고, 앱 안에서 미리보기로 연다.

## 7. 화면

### 7.1 디자인 방향 — 토스 앱 같은 분위기
- 흰 배경과 넓은 여백, 큰 글씨의 제목, 카드형 목록, 둥근 모서리, 파란 강조색 하나
- 한 화면에 큰 일 하나만: 버튼은 화면 아래 큰 버튼 하나를 중심으로
- 글꼴은 Pretendard(오픈 라이선스)
- **토스의 로고, 이름, 아이콘, 전용 글꼴 같은 브랜드 자산은 쓰지 않는다.** 분위기만 참고한다
- 다크 모드는 처음부터 색 토큰으로 지원한다

### 7.2 화면 목록
- **로그인·회원가입**: 이메일, 비밀번호, 이름
- **Claude 로그인 상태**: 앱이 켜질 때 `claude auth status` 로 확인한다. 안 돼 있으면 [Claude 로그인] 버튼을 보여 주고, 누르면 공식 `claude auth login` 을 실행한다(터미널 로그인과 같은 브라우저 창). 로그인 정보는 Claude Code 가 저장하고 앱은 다루지 않는다
- **방 목록**: 카드마다 방 이름, 최근 메시지, 지금 실행 중 표시. 아래에 [방 만들기], [초대 코드로 참가]
- **방 화면**
  - 가운데 채팅: 보낸 사람 이름, 메시지, `@claude` 요청은 상태 배지(대기, 실행 중, 완료, 실패, 보류), Claude 답은 실시간으로 보여 준다. 도구 실행 내역은 접어 둔다
  - 오른쪽 패널 탭
    - [레포]: 레포마다 내 로컬 경로, 현재 브랜치, 경고
    - [공유 파일]: 메모리, md, HTML 미리보기
    - [멤버]: 멤버와 방장, 대기열 순서
  - 입력창: 언제든 입력할 수 있다. `@claude` 로 시작하면 Claude 요청이 된다
  - 승인 창: 보낸 사람 화면에만 뜬다. 실행하려는 명령이나 파일과 [허용] [거부]
- **방 설정(방장만)**: 방 이름, 초대 코드 재발급, 레포·브랜치 추가·수정·삭제, 방 삭제
- **방 나가기**: 방 목록과 방 설정에서

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 실행 중 앱 종료·네트워크 끊김 | 30초 신호 없음 → `failed`(중단됨). 대화 원본은 마지막으로 올라온 버전을 유지 |
| 사용량 한도 초과 | `failed` + "A 계정 한도 초과" 표시. 다른 사람이 이어서 보내면 됨 |

| 늦게 도착한 결과(버전 불일치) | 서버가 거부하고 앱에 알림 |
| 서버 재시작 | SQLite·파일에서 그대로 복구. 실행 중이던 요청은 `failed` 처리 |

## 9. 보안

- 1단계는 사내 네트워크 안에서 `http`/`ws` 로 쓴다. **비밀번호와 대화 내용이 암호화되지 않고 오간다.** 클라우드로 옮길 때 TLS 를 붙인다.
- 대화 원본과 공유 파일에는 코드, DB 조회 결과, 고객사명이 들어갈 수 있다. 서버 데이터 폴더는 레포에 커밋하지 않는다.
- 서버는 Claude 로그인 정보를 다루지 않는다.

## 10. 확인되지 않은 것 (0단계 시험으로 먼저 확인)

|---|---|---|

|---|---|
| R2 | **통과.** `-p --resume <id>` 는 같은 세션 ID, 같은 jsonl 파일에 이어 쓴다 |
| R1 (다른 경로) | **통과.** jsonl 을 다른 폴더의 인코딩 위치로 복사하고 그 폴더에서 `--resume` 하면 대화를 기억하고, 복사본에 이어 쓴다. 인코딩 = 절대 경로에서 영숫자가 아닌 글자를 `-` 로 |
| R1 (다른 계정, 같은 조직) | **통과.** 같은 조직(팀 플랜)의 다른 계정으로 A 가 만든 대화를 `--resume` → 이어짐. 그 결과를 다시 A 로 `--resume` → 이어짐(42 → 43 → 44). 세션 ID 는 처음 것 그대로, 오류 없음. `session-owner` 기록은 만든 사람(A) 값만 남는다 |
| R1 (다른 계정, 가짜 소유자) | **부분 확인.** jsonl 에 `session-owner` 기록(accountUuid·organizationUuid)이 있다. 이 값을 가짜 UUID 로 바꾼 파일도 A 계정에서 `--resume` 하면 정상으로 이어졌다 → 로컬 클라이언트는 소유자 불일치로 막지 않는다. 실제 다른 유료 계정으로는 아직 못 해 봄(B 계정이 무료 플랜이라 Claude Code 실행 불가). 공식 에러 목록에 `This conversation ran under organization` / `…more than one organization` 메시지가 있어 **조직이 다르면 이어 가기를 경고하거나 막는 장치가 있다.** 조건은 문서에 없고, 가짜 조직 ID 시험(-p)에서는 나오지 않았다([errors](https://code.claude.com/docs/en/errors.md)) |
| R1 (맥2) | 대기 |
| R3 | **통과.** 승인 도구 입력은 `{tool_name, input, tool_use_id}`. `allow` + `updatedInput` 이면 실행, `deny` 면 막히고 결과의 `permission_denials` 에 남는다 |

추가로 알게 된 것:
- 사용자의 기본 권한 모드가 `auto` 면 승인 도구가 **한 번도 불리지 않는다**(자동 판정으로 처리). `--permission-mode default` 를 주면 허용 목록에 없는 것만 승인 도구로 온다
- 짧은 대화 두 번에도 jsonl 이 약 580KB 였다(훅·시스템 문맥 포함). 대화 원본 전송량이 생각보다 크다
- **세션 압축**: `claude -p "/compact" --resume <id>` 가 헤드리스에서도 된다. 같은 jsonl 에 `compact_boundary` 와 요약 줄이 추가되고 세션 ID 는 그대로다. 압축 뒤에도 앞 내용을 기억했다. 압축 전 줄은 파일에 남으므로 파일 크기는 줄지 않는다
- **Claude Code 는 Pro 이상 유료 플랜이 있어야 실행된다.** 무료 계정은 로그인 뒤 업그레이드를 요구한다. 방에서 `@claude` 를 쓰려면 모두 유료 플랜이 필요하다
- jsonl 에는 계정 UUID, 조직 UUID, 사용자 이메일이 들어 있다. 대화 원본을 방 사람들과 공유하면 이 값도 같이 공유된다
- stdin 을 비우지 않으면 `no stdin data received in 3s` 경고와 함께 3초 기다린다 → 실행기는 stdin 을 닫고 실행한다

## 11. 테스트

- **0단계 시험**: 10장 R1~R3 를 맥 두 대로 확인한다. 결과는 이 문서에 적는다.
- **서버 단위 테스트**: 방 만들기·참가·나가기, 방장 이전, 대기열 순서, 신호 시간 초과, 버전 불일치 거부
- **실행기 통합 테스트**: `claude -p` 를 실행하고 stream-json 을 읽어 이벤트로 바꾸는 부분 1개
- **수동 시나리오**: 맥 두 대로 ① 방 만들고 참가 ② 사람 채팅 ③ A `@claude` → B `@claude` 로 대화 이어짐 확인 ④ 실행 중 B 요청 대기열 ⑤ 승인 창 ⑥ 공유 파일 동기화 ⑦ 레포 브랜치 불일치 차단 ⑧ 방 나가기
